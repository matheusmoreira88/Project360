| 5 — GPU | PM4 framing, draw/index processing, VFETCH conversion and first vector/scalar ALU pairs; incomplete | A dependency-free decoder recognizes big-endian type-0/1 register packets, type-2 no-ops and type-3 command boundaries. Type-0/1 writes and the type-3 `SET_CONSTANT`, `SET_CONSTANT2` and `SET_SHADER_CONSTANTS` uploads apply to a caller-sized register file transactionally. `DRAW_INDX`/`DRAW_INDX_2` metadata is decoded and known writes to `VGT_DRAW_INITIATOR`/DMA registers are applied transactionally. DMA index fetching reads physical backing memory, validates declared element counts, applies supported endian modes and generates auto-index values. `prepare_draw_geometry` connects DMA/auto-index fetching, CPU topology assembly and the mapped vertex-index offset/wrap/clamp state. It handles points, lines, line strips, triangle lists/strips, fans, line loops and quad lists; fans, loops and quads become indexed ranges. Configured restart values split modeled line strips, triangle strips, fans and line loops. Vertex fetch decodes the two-dword buffer descriptor, reads bounded physical dword ranges with all four endian modes, and decodes three-dword VFETCH instructions. The attribute reader computes indexed addresses from dword stride and signed offset, distinguishes logical components from storage dwords, and converts packed 8/10/11-bit and 16-bit formats, IEEE binary16, plus existing 32-bit integer/float formats. Unsigned/signed integer and normalized conversion are covered; alternate signed repeating-fraction mapping and nonzero exponent adjustment fail explicitly. The combined `execute_vertex_fetch_attribute` path selects and rounds the source index, reads and converts the bounded attribute, fills absent lanes from caller-supplied values, and applies destination swizzles. The ordered VFETCH runner evaluates decoded instructions against a 64-register temporary bank and fetch-constant slots; relative addressing and missing descriptors fail explicitly. The `shader_alu` module decodes one three-dword instruction, resolves temporary sources or absolute-addressed float constants with relative swizzle, absolute-value and negate modifiers, and evaluates vector ADD/MUL/MAX/MIN/SEQ/SGT/SGE/SNE/FRC/TRUNC/FLOOR/CNDE/CNDGE/CNDGT/DP4/DP3/DP2ADD paired with scalar ADDS/ADDS_PREV/MULS/MULS_PREV/MULS_PREV2/MAXS/MINS/SEQS/SGTS/SGES/SNES/FRCS/TRUNCS/FLOORS/RCPC/RCPF using the documented W/X components of `src3`. Both halves read the original register bank and commit masked writes together; scalar previous-state updates are tested even when its destination mask is empty. The ordered EXEC runner carries this `ps` state across ALU slots and preserves it through VFETCH slots. The standalone vector evaluator covers the same operations, replicates DP3/DP4/DP2ADD sums with separately rounded legacy products (DP4 currently uses XYZW; source documents conflict on accumulator order), and rejects MAX/MIN lanes with NaN inputs until Xenos-specific unordered behavior is verified; MUL/MULS zero and subnormal operands return positive zero under the documented legacy rule. RCPC/RCPF use host reciprocal results with limited special-value tests; Xenos reciprocal precision and IEEE RCP remain unvalidated. The straight-line shader EXEC runner synchronously schedules supported ALU pairs and full VFETCH instructions over a shared register bank; its synthetic three-operation dependency chain passes. Vector MULADD (11) pending fused/unfused precision resolution, other ALU operations, a0/aL-relative constants, loops, exports, conditional control flow, predicates, texture fetch, shader timing, clipping, Vulkan and rendering remain unimplemented. See [Xenos shader work](hardware/xenos_shader.md). Vulkan SDK is not installed on the current development PC. |

The CPU subset also now executes the optional indexed PowerPC `stfiwx` transfer. Tests verify raw low-word storage, state preservation, reserved encoding rejection and alignment faults; support for this optional instruction is an emulator capability, not evidence that a particular Xenon revision implements it. Concurrent interpreter contexts execute `lwarx`/`stwcx.` and `ldarx`/`stdcx.` against shared GuestMemory with locked conditional stores and 4 KiB backing-page generations; two-context word and doubleword increment tests verify exact results. `sync` and `lwsync` execute as conservative host fences, but Xenon thread scheduling, weak-memory outcomes, GPU coherence, `eieio`/MMIO ordering and measured Xenon reservation-granule behavior remain open.

## Frontend status

The optional Qt 6 Widgets source now defines a dark Project360 shell, model-backed library, persistent local `.xex` paths, case-insensitive name search, name ordering, path removal, and explicit unavailable states. The independent library store has bounded, versioned parsing and passing unit tests. Windows CI compiled the GUI and passed the Qt model and offscreen window smoke tests in Debug and Release ([run 42451851613](https://github.com/matheusmoreira88/Project360/actions/runs/42451851613)). Manual visual review has not been performed, and core emulator phases remain independent of this optional target.

## Next engineering step

Continue closing the homebrew startup gaps with authorized, unencrypted XEX runs and explicit unsupported-instruction/import diagnostics. For 3D, expand the validated ALU operation set, then implement conditional control flow, loops and vertex exports before Vulkan pipeline integration. Do not make a 2D title a gate before this work; a lightweight 2D title can be an optional regression target later. The current GPU still cannot execute a complete shader or render a frame. The CLI supports XEX2 with no/basic compression, creates a minimal main-thread context with a partial KTHREAD data block but no handles or scheduler, and stops after one million instructions or on a reported execution fault. Encrypted and LZX-compressed XEX files remain unsupported. GTA V stays a later target after homebrew and 3D evidence.
