# Roadmap and verified status

The roadmap tracks evidence rather than estimated completion percentages.

| Phase | Status | Evidence / acceptance still needed |
|---|---|---|
| 0 — Foundation | Locally and remotely verified | CMake configure succeeded with CMake 4.3.1 and MSVC 19.51; Debug and Release builds completed; CTest passed in both configurations; smoke executable ran. Core Windows CI also passed on the Windows 2022 runner ([run 42451851612](https://github.com/matheusmoreira88/Project360/actions/runs/42451851612)). |
| 1 — PowerPC interpreter | Incremental subset implemented and locally tested; incomplete | Debug and Release builds and CTest pass. Tests cover illegal/privileged program exception entry to vector `0x700`, `sc 0` system-call entry to `0xC00` and return through `rfid`, `isync`/`sync`/`lwsync` encoding, reserved-field checks and fresh code fetch, cache-maintenance no-ops, accepted prefetch hints and 128-byte `dcbz` writes with bounds/reservation checks, SRR0/SRR1 capture, privileged SRR access, scalar FPR memory transfers in D/indexed forms, bit-exact `fmr`, `fneg`, `fabs`, `fnabs`, `neg`/`nego`, `addme`/`subfme`/`subfze`, `mulhw`, `mulhwu`, `mulhd`, `mulhdu`, `sradi` including the split six-bit shift field, XER.CA and Rc, and signed/unsigned `divw`, `divwu`, `divd`, `divdu` including OE/Rc and invalid divide cases. Undefined word-result upper bits and division results use documented deterministic interpreter values. Kernel syscall dispatch, hypervisor calls, general floating-point arithmetic/FPSCR control, other exception classes, Xenon-specific MSR behavior, VMX128, Xenon multicore scheduling, weak-memory outcomes and most instructions remain absent. |
| 2 — Memory subsystem | Mapping prototype implemented; incomplete | Opt-in 4 KiB guest-page mapping, virtual aliases, read/write/execute permissions, bounded physical backing, CPU execute-permission checks, and transactional byte/pattern fill and guest byte stores across non-contiguous mapped pages are covered by tests. Xenon-specific translation, MMIO, the full Xenon memory model, CPU/GPU coherence and memory budgeting remain unimplemented. |
| 3 — Loader | Unencrypted XEX2 loading and import decoding started; incomplete | Bounded metadata parsing validates the Import Libraries optional header, aligned names, descriptor sizes, versions, counts and record addresses. During load, import record bytes are decoded and checked against the library index, PE bounds and supported record types before page mappings are created. Synthetic valid and malformed fixtures cover these checks. Encrypted/compressed formats and real title startup remain unsupported. |
| 4 — Kernel | Thirteen exports dispatched; twelve exercised through a synthetic loaded XEX; incomplete | A guest executor indexes function-import thunk addresses and dispatches `xboxkrnl.exe` ordinals 268 (`RtlCompareMemory`), 269 (`RtlCompareMemoryUlong`), 284 (`RtlFillMemory`), 285 (`RtlFillMemoryUlong`), 289 (`RtlInitAnsiString`), 290 (`RtlInitUnicodeString`), 293 (`RtlIntegerToUnicodeString`), 298 (`RtlMoveMemory`), 301 (`RtlNtStatusToDosError`), 307 (`RtlUlongByteSwap`), 309 (`RtlUnicodeStringToInteger`), 318 (`RtlUshortByteSwap`) and 320 (`RtlZeroMemory`) with Xenon arguments, returning through LR. The synthetic XEX caller converts a counted UTF-16 hexadecimal string to an integer and formats an integer as uppercase hexadecimal, checking both return statuses and resumed guest execution. Direct tests cover radices, buffer overflow/required length, invalid base, guest memory faults and the partial NTSTATUS mapping. Unknown exports and attempted execution of data imports fault explicitly. Data imports are parsed but not resolved; broader service states, syscall/exception routing and most kernel exports remain unimplemented. |
| 5 — GPU | PM4 framing and register uploads started; incomplete | A dependency-free decoder recognizes big-endian type-0/1 register packets, type-2 no-ops and type-3 command boundaries. Type-0/1 writes and the type-3 `SET_CONSTANT`, `SET_CONSTANT2` and `SET_SHADER_CONSTANTS` uploads apply to a caller-sized register file transactionally. PM4 NOP is accepted; unimplemented opcodes, predicated uploads and incomplete packet lists fail explicitly. Tests cover constant-bank mapping, mixed packets, repeated writes, transactional failures, bounds failures, unsupported banks and truncated payloads. Xenos register semantics beyond these upload formats and rendering are not implemented. Vulkan SDK is not installed on the current development PC; no Xenos draw or shader has been executed. |
| 6 — Audio, input and storage | Not started | Device integration tests. |
| 7 — IR/JIT | Not started | Differential correctness and measured speedup. |
| 8 — Integration | Bounded synthetic XEX execution started; incomplete | `GuestExecutor::run` executes a loaded image through CPU instructions and implemented kernel-import thunks up to a finite instruction budget, continuing through modeled exceptions and returning explicit fault/budget stops. A synthetic XEX test verifies all ten imports and exact budget termination. The CLI `--run-xex` path allocates guest memory, loads supported unencrypted/uncompressed XEX2 and executes up to one million instructions. No external homebrew or commercial title has been run; startup services, process/thread initialization, GPU, audio and input integration remain incomplete. |
| 9 — GTA V / other games | Not started | No game loading or execution is currently supported. |
| 10 — Performance | Not started | Reproducible benchmarks and profiling. |
| 11 — Expansion | Not started | Depends on prior compatibility evidence. |

The CPU subset also now executes the optional indexed PowerPC `stfiwx` transfer. Tests verify raw low-word storage, state preservation, reserved encoding rejection and alignment faults; support for this optional instruction is an emulator capability, not evidence that a particular Xenon revision implements it. Concurrent interpreter contexts now execute `lwarx`/`stwcx.` against shared GuestMemory with locked conditional stores, 4 KiB backing-page generations and a two-context increment test. `sync` and `lwsync` execute as conservative host fences, but Xenon thread scheduling, weak-memory outcomes, GPU coherence, `eieio`/MMIO ordering and measured Xenon reservation-granule behavior remain open.

## Frontend status

The optional Qt 6 Widgets source now defines a dark Project360 shell, model-backed library, persistent local `.xex` paths, case-insensitive name search, name ordering, path removal, and explicit unavailable states. The independent library store has bounded, versioned parsing and passing unit tests. Windows CI compiled the GUI and passed the Qt model and offscreen window smoke tests in Debug and Release ([run 42451851613](https://github.com/matheusmoreira88/Project360/actions/runs/42451851613)). Manual visual review has not been performed, and core emulator phases remain independent of this optional target.

## Next engineering step

Map the Xenos register ranges and write masks on top of the generic PM4 register file, then dispatch the first documented type-3 operations. Add Vulkan resource and pipeline work when the SDK is available. The current GPU path explicitly rejects draw opcodes and predicated commands; it does not interpret shaders or render. The current CLI can load only unencrypted/uncompressed XEX2 and will stop after one million instructions or on a reported execution fault. Encrypted/compressed commercial XEX files remain unsupported, and real title execution also requires broader CPU semantics, imports and kernel services.
