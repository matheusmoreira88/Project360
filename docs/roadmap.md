Core Windows CI also passed on the Windows 2022 runner ([run 42451851612](https://github.com/matheusmoreira88/Project360/actions/runs/42451851612)). |
| 1 — PowerPC interpreter | Incremental subset implemented and locally tested; incomplete | Debug and Release builds and CTest pass. Tests cover illegal/privileged program exception entry to vector `0x700`, trap-word/doubleword immediate and register forms with SRR1 trap syndrome, `sc 0` system-call entry to `0xC00` and return through `rfid`, `isync`/`sync`/`lwsync` encoding, reserved-field checks and fresh code fetch, cache-maintenance no-ops, accepted prefetch hints and 128-byte `dcbz` writes with bounds/reservation checks, SRR0/SRR1 capture, privileged SRR access, scalar FPR memory transfers in D/indexed forms, bit-exact `fmr`, `fneg`, `fabs`, `fnabs`, `fcmpu`/`fcmpo` ordered comparisons and quiet-NaN unordered compare, `neg`/`nego`, `addme`/`subfme`/`subfze`, `mulhw`, `mulhwu`, `mulhd`, `mulhdu`, `sradi` including the split six-bit shift field, XER.CA and Rc, and signed/unsigned `divw`, `divwu`, `divd`, `divdu` including OE/Rc and invalid divide cases. Xenon-specific translation, MMIO, the full Xenon memory model, CPU/GPU coherence and memory budgeting remain unimplemented. |
| 3 — Loader | Unencrypted XEX2 loading and import decoding started; incomplete | Bounded metadata parsing validates the Import Libraries optional header, aligned names, descriptor sizes, versions, counts and record addresses; Execution Info extracts media/title IDs, title/base versions, platform, executable type, disc numbering, savegame ID and the 16-byte TLS template descriptor. Loading rejects TLS sizes beyond the loader budget, raw data larger than the declared area, and templates outside the mapped image. Synthetic valid and malformed fixtures cover these checks. During load, import record bytes are decoded and checked against the library index, PE bounds and supported record types before page mappings are created. Synthetic fixtures cover page-descriptor metadata and permission checks, unencrypted basic-compression reconstruction and bounds failures. Encrypted images, LZX/other compression formats and real title startup remain unsupported. |
| 4 — Kernel | Nineteen exports dispatched; minimal main-thread launch context started; incomplete | `initialize_main_thread_context` allocates mapped TLS, PCR, stack and an unmapped guard page; copies the XEX static TLS template; writes the documented PCR TLS/self/stack/CPU/DPC fields; and initializes guest `r1`, `r13` and PC. Synthetic XEX tests validate copied template bytes, zero-filled TLS tail, PCR fields, stack state, guard page and bounded-allocation failure. `--run-xex` uses this bootstrap and passes its bounded TLS slot array to the kernel dispatcher. The current-thread pointer in PCR remains zero because KTHREAD objects and scheduling do not exist. The dispatcher supports nineteen modeled `xboxkrnl.exe` exports, including `KeTlsAlloc`, `KeTlsFree`, `KeTlsGetValue` and `KeTlsSetValue`; unknown exports and attempted execution of data imports fault. | 5 — GPU | PM4 framing and register uploads started; incomplete | A dependency-free decoder recognizes big-endian type-0/1 register packets, type-2 no-ops and type-3 command boundaries. Type-0/1 writes and the type-3 `SET_CONSTANT`, `SET_CONSTANT2` and `SET_SHADER_CONSTANTS` uploads apply to a caller-sized register file transactionally. PM4 NOP is accepted; unimplemented opcodes, predicated uploads and incomplete packet lists fail explicitly. Tests cover constant-bank mapping, mixed packets, repeated writes, transactional failures, bounds failures, unsupported banks and truncated payloads. Xenos register semantics beyond these upload formats and rendering are not implemented. Vulkan SDK is not installed on the current development PC; no Xenos draw or shader has been executed. |

The CPU subset also now executes the optional indexed PowerPC `stfiwx` transfer. Tests verify raw low-word storage, state preservation, reserved encoding rejection and alignment faults; support for this optional instruction is an emulator capability, not evidence that a particular Xenon revision implements it. Concurrent interpreter contexts now execute `lwarx`/`stwcx.` against shared GuestMemory with locked conditional stores, 4 KiB backing-page generations and a two-context increment test. `sync` and `lwsync` execute as conservative host fences, but Xenon thread scheduling, weak-memory outcomes, GPU coherence, `eieio`/MMIO ordering and measured Xenon reservation-granule behavior remain open.

## Frontend status

The optional Qt 6 Widgets source now defines a dark Project360 shell, model-backed library, persistent local `.xex` paths, case-insensitive name search, name ordering, path removal, and explicit unavailable states. The independent library store has bounded, versioned parsing and passing unit tests. Windows CI compiled the GUI and passed the Qt model and offscreen window smoke tests in Debug and Release ([run 42451851613](https://github.com/matheusmoreira88/Project360/actions/runs/42451851613)). Manual visual review has not been performed, and core emulator phases remain independent of this optional target.

## Next engineering step

Map the Xenos register ranges and write masks on top of the generic PM4 register file, then dispatch the first documented type-3 operations. Add Vulkan resource and pipeline work when the SDK is available. The current GPU path explicitly rejects draw opcodes and predicated commands; it does not interpret shaders or render. The current CLI can load unencrypted XEX2 with no/basic compression, create only a minimal main-thread context (without a KTHREAD object or scheduler), and stop after one million instructions or on a reported execution fault. Encrypted and LZX-compressed commercial XEX files remain unsupported, and real title execution also requires broader CPU semantics, imports and kernel services.
