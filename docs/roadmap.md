# Roadmap and verified status

The roadmap tracks evidence rather than estimated completion percentages.

Latest GPU increment: PM4 `IM_LOAD` and `IM_LOAD_IMMEDIATE` capture bounded vertex/pixel microcode into immutable draw snapshots; `LOAD_ALU_CONSTANT` loads bounded dwords from guest memory into ALU, fetch, boolean, loop or direct-register banks. The Vulkan offscreen smoke consumes guest-memory-loaded c7 through the retained draw snapshot, CPU shader reference path and hardware rasterization; a second synthetic draw verifies a nonzero constant changes the CPU vertex position by the expected delta. The stream processor tracks bin mask/selection state and applies it to predicated type-3 packet dispatch. Synthetic tests connect captured vertex code to the explicit-prefix CPU EXEC reference runner and reject malformed loads. Texture blocks support descriptor swizzles and float numeric conversion for format 6 (8:8:8:8), plus unsigned, unsigned-biased and RGB-gamma modes for DXT1/3/5; signed DXT and unverified storage formats return explicit errors. Integer-coordinate point reads compose tiled memory access, endian conversion, block decoding, numeric interpretation and swizzle for format 6 and DXT1/3/5. Normalized-UV nearest and bilinear sampling now resolve repeat, mirror, edge clamp and mirror-once edge clamp. Bilinear filtering converts four addressed taps before interpolation; integer number format and out-of-range border/halfway taps remain unsupported, as does shader translation. This does not execute external titles or translate game shaders; details are in [Xenos shader work](hardware/xenos_shader.md).

## Current GPU milestone
The shader-side three-dword `tfetch` decoder now executes normalized coordinates against the referenced PM4 texture descriptor for a tiled, non-stacked 2D base-level texture when min/mag resolve to the same point or linear filter. A synthetic draw test carries the sample through a vertex-position export. Relative registers, predication, unnormalized coordinates, differing filters, LOD/gradients, offsets, anisotropy, mip levels, pixel-shader execution and game rendering remain unsupported.


The bounded raster-state path decodes Xenos screen/window scissor registers, applies the signed window offset when enabled, intersects with the screen scissor and clips to the selected target. The Vulkan smoke test drives those values through a synthetic PM4 draw and verifies partial coverage on the RTX 5050. Debug and Release builds and all configured tests passed with and without the optional Vulkan backend. The tested subset includes clipped X/Y mapping, D3D and symmetric -W-to-W depth clipping, and bounded Z scale/offset mapping. Clipping-disabled draws and user clip planes remain unsupported. Guest shader translation, presentation and game compatibility are still absent. The compatibility ladder remains at synthetic tests; no homebrew or game has run.

The texture-memory path accepts a decoded fetch constant, reads base-level blocks for supported non-stacked tiled 2D descriptors and applies all four Xenos endian modes to aligned physical byte lanes. The pixel-block decoder expands formats 4, 6, 18, 19 and 20 (RGB565, 8:8:8:8, DXT1, DXT3 and DXT5) into RGBA8 texels, with synthetic checks for packed channels, endpoint expansion, palette interpolation and both explicit and interpolated alpha modes. Debug, Release and Vulkan Debug builds and all configured CTest targets pass. Numeric sign/gamma and component swizzles, linear layouts, mip addressing, cube/3D/stacked textures and shader sampling remain open, so the decoded blocks are not yet connected to a game shader or frame.

The CPU subset also now executes the optional indexed PowerPC `stfiwx` transfer. Tests verify raw low-word storage, state preservation, reserved encoding rejection and alignment faults; support for this optional instruction is an emulator capability, not evidence that a particular Xenon revision implements it. Concurrent interpreter contexts execute `lwarx`/`stwcx.` and `ldarx`/`stdcx.` against shared GuestMemory with locked conditional stores and 4 KiB backing-page generations; two-context word and doubleword increment tests verify exact results. `sync` and `lwsync` execute as conservative host fences, but Xenon thread scheduling, weak-memory outcomes, GPU coherence, `eieio`/MMIO ordering and measured Xenon reservation-granule behavior remain open.

## Frontend status

The optional Qt 6 Widgets source now defines a dark Project360 shell, model-backed library, persistent local `.xex` paths, case-insensitive name search, name ordering, path removal, and explicit unavailable states. The independent library store has bounded, versioned parsing and passing unit tests. Windows CI compiled the GUI and passed the Qt model and offscreen window smoke tests in Debug and Release ([run 42451851613](https://github.com/matheusmoreira88/Project360/actions/runs/42451851613)). Manual visual review has not been performed, and core emulator phases remain independent of this optional target.

## Next engineering step

Continue closing the homebrew startup gaps with authorized, unencrypted XEX runs and explicit unsupported-instruction/import diagnostics. For 3D, expand the validated ALU operation set, then implement conditional control flow, loops and vertex exports before connecting Xenos output to the Vulkan pipeline. The Vulkan backend now rasterizes a synthetic triangle, but it still cannot execute a complete Xenos shader or render a game frame. Do not make a 2D title a gate before this work; a lightweight 2D title can be an optional regression target later. The CLI supports XEX2 with no/basic compression, creates a minimal main-thread context with a partial KTHREAD data block but no handles or scheduler, and stops after one million instructions or on a reported execution fault. Encrypted and LZX-compressed XEX files remain unsupported. GTA V stays a later target after homebrew and 3D evidence.
