| 3 — Loader | Unencrypted XEX2 loading and import decoding started; incomplete | Bounded metadata parsing validates the Import Libraries optional header, aligned names, descriptor sizes, versions, counts and record addresses; Execution Info extracts media/title IDs, title/base versions, platform, executable type, disc numbering, savegame ID and the 16-byte TLS template descriptor. CPU topology assembly handles points, lines, line strips, triangle lists/strips, fans, line loops and quad lists; fans, loops and quads become indexed ranges. Configured restart values split modeled line strips, triangle strips, fans and line loops. Tests cover descriptor fields, physical bounds, endian modes, restart splits, topology conversion and vertex-index boundaries. The CPU subset also now executes the optional indexed PowerPC `stfiwx` transfer. Tests verify raw low-word storage, state preservation, reserved encoding rejection and alignment faults; support for this optional instruction is an emulator capability, not evidence that a particular Xenon revision implements it. Concurrent interpreter contexts now execute `lwarx`/`stwcx.` against shared GuestMemory with locked conditional stores, 4 KiB backing-page generations and a two-context increment test. `sync` and `lwsync` execute as conservative host fences, but Xenon thread scheduling, weak-memory outcomes, GPU coherence, `eieio`/MMIO ordering and measured Xenon reservation-granule behavior remain open.

## Frontend status

The optional Qt 6 Widgets source now defines a dark Project360 shell, model-backed library, persistent local `.xex` paths, case-insensitive name search, name ordering, path removal, and explicit unavailable states. The independent library store has bounded, versioned parsing and passing unit tests. Windows CI compiled the GUI and passed the Qt model and offscreen window smoke tests in Debug and Release ([run 42451851613](https://github.com/matheusmoreira88/Project360/actions/runs/42451851613)). Manual visual review has not been performed, and core emulator phases remain independent of this optional target.

## Next engineering step

Map the Xenos register ranges and write masks on top of the generic PM4 register file, then connect decoded draw metadata to explicit guest state and a graphics backend. Add Vulkan resource and pipeline work when the SDK is available. The current GPU path can inspect a narrow set of draw packets but does not execute draws, interpret shaders or render; predicated and immediate-index draws remain explicitly unsupported. The current CLI can load unencrypted XEX2 with no/basic compression, create a minimal main-thread context with a partial KTHREAD data block but no handles or scheduler, and stop after one million instructions or on a reported execution fault. Encrypted and LZX-compressed commercial XEX files remain unsupported, and real title execution also requires broader CPU semantics, imports and kernel services.
