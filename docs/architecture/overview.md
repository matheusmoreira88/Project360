# Initial architecture

The first build has three small layers:

- `memory::GuestMemory` owns a bounded byte buffer and exposes big-endian 8-, 16-, 32- and 64-bit accesses. Multi-byte accesses enforce natural alignment in this prototype. It is a test memory model, not the Xbox 360 virtual memory system.
- `cpu::decode` converts a 32-bit PowerPC instruction word into a typed operation or an explicit diagnostic.
- `cpu::Interpreter` executes one instruction or a bounded sequence against `CpuState` and guest memory. Current compare instructions update the selected CR field; conditional branches use CR bits and CTR according to their BO/BI fields. Unsupported or reserved forms return a fault instead of silently succeeding.

`CpuState` includes 32 FPR bit containers and an FPSCR storage field. Scalar `lfs`, `lfd`, `stfs`, and `stfd` transfers work in D and indexed forms, including update variants. `lfs` widens an IEEE binary32 value into the binary64 FPR representation; `stfs` converts back to binary32. Indexed `stfiwx` stores the low 32 bits of an FPR unchanged as a big-endian word; it does not convert the value or modify CR0/FPSCR. Bitwise unary `fmr`, `fneg`, `fabs` and `fnabs` preserve payload bits; their record forms copy FPSCR summary bits to CR1. `fcmpu` and `fcmpo` compare non-NaN binary64 FPR values and update the selected CR field plus FPSCR FPCC; unordered quiet-NaN `fcmpu` sets FU. NaN cases that require FPSCR invalid-operation exception behavior are explicitly diagnosed as unsupported without partial state changes. Floating arithmetic, general FPSCR writes/exception routing, denormal exception behavior and VMX128 are not implemented, so this subset does not support floating-point programs generally. Opcode and compare behavior references: IBM [PowerPC instruction reference](https://www.ibm.com/docs/en/aix/7.1.0?topic=reference-appendix-f-powerpc-instructions), [fcmpu](https://www.ibm.com/docs/en/aix/7.1.0?topic=set-fcmpu-floating-compare-unordered-instruction), [fcmpo](https://www.ibm.com/docs/ssw_aix_71/assembler/idalangref_fcmpo_instrs.html), [fmr](https://www.ibm.com/docs/en/aix/7.2.0?topic=set-fmr-floating-move-register-instruction) and [stfiwx](https://www.ibm.com/docs/en/aix/7.1.0?topic=is-stfiwx-store-floating-point-as-integer-word-indexed).

The privileged `mfmsr` instruction copies the complete modeled MSR into a GPR in supervisor state; problem state takes the modeled privileged-instruction exception. Its opcode and privilege level follow IBM's [PowerPC `mfmsr` reference](https://www.ibm.com/docs/en/aix/7.1.0?topic=set-mfmsr-move-from-machine-state-register-instruction). This does not imply complete Xenon MSR semantics or implement `mtmsr`.

The implemented `mtmsrd L=1` form changes only MSR[EE] and MSR[RI]; it is privileged and preserves every other modeled MSR bit. `mtmsrd L=0` is decoded but returns an explicit unsupported-instruction fault because its broader context transition is not modeled. The L=1 write mask follows the public [PowerPC Operating Environment Architecture, Book III v2.02](https://powerpc.dev/general/PPC_Vers202_Book3_public.pdf). Instruction/context synchronization beyond the interpreter's sequential execution model remains unimplemented.

## Memory mapping prototype

`GuestMemory` retains a bounded byte buffer as physical backing storage. Page mapping is opt-in, uses a fixed 4 KiB page size in this prototype, supports aliases, and checks read/write/execute access separately. CPU instruction fetch now requests execute permission, while data operations request read or write permission. `load()` is a host-side initialization path to populate backing bytes. `read_physical()` exposes a bounded raw backing-store read for devices such as GPU DMA, without applying CPU virtual mappings. Public reads use shared locking and writes/mapping changes use exclusive locking, so multiple host execution contexts can safely access this prototype. This remains generic virtual-to-physical translation only: it has no Xenon segment/page-table rules, MMIO, shared CPU/GPU coherence, the full Xenon memory model, demand paging, or 512 MB console memory model.

`lwarx`/`stwcx.` and `ldarx`/`stdcx.` provide word and doubleword load-reserve and conditional-store behavior across concurrent interpreter contexts. Each reservation load captures the physical address, backing-page generation and value under a shared lock; its conditional store checks the token and commits the value plus generation update under an exclusive lock. All GuestMemory write paths invalidate reservations on the touched 4 KiB backing page, including typed stores, byte ranges, fill, move, loader writes and aliases. At 512 MiB of backing memory, the generation table adds 1 MiB of host memory. A conditional store must target the same physical address; CR0 records success and XER.SO. The 4 KiB reservation granule is an explicit prototype choice, not a measured Xenon granule. The CPU contexts are host-created tests only: there is no Xenon hardware-thread scheduler, guest thread state, or GPU coherence. Instruction encodings and semantics were checked against IBM's [`lwarx`](https://www.ibm.com/docs/en/aix/7.2.0?topic=set-lwarx-load-word-reserve-indexed-instruction), [`stwcx.`](https://www.ibm.com/docs/en/aix/7.1.0?topic=set-stwcx-store-word-conditional-indexed-instruction), [`ldarx`](https://www.ibm.com/docs/en/aix/7.1.0?topic=set-ldarx-load-doubleword-reserve-indexed-instruction) and [`stdcx.`](https://www.ibm.com/docs/en/aix/7.1.0?topic=set-stdcx-store-double-word-conditional-indexed-instruction) references.


## Fixed-point string transfers

`lswi` and `stswi` transfer the immediate NB count, with zero meaning 32 bytes. `lswx` and `stswx` use XER's low seven-bit byte count; a zero indexed-load count leaves its target registers unchanged as a deterministic choice for the architecturally undefined case. Transfers proceed byte-by-byte from the most-significant byte of each low 32-bit GPR word, wrap register numbers modulo 32, and do not require alignment. Loads clear each destination GPR's upper 32 bits, zero-fill unfilled bytes in a partial final word, and stage all destination words before committing. Stores use `GuestMemory::write_bytes` to validate the complete range before any byte is written. `lswi` base overlap is rejected during decoding; `lswx` address-register overlap is diagnosed at execution because its target range depends on XER.BC. The operation and field rules are cross-checked against IBM's [`lswi`](https://www.ibm.com/docs/ssw_aix_71/assembler/idalangref_lswi_instrs.html), [`lswx`](https://www.ibm.com/docs/en/aix/7.1.0?topic=set-lswx-lsx-load-string-word-indexed-instruction), [`stswi`](https://www.ibm.com/docs/ssw_aix_71/assembler/idalangref_stswi_instrs.html) and [`stswx`](https://www.ibm.com/docs/en/aix/7.2.0?topic=set-stswx-stsx-store-string-word-indexed-instruction) references.

`isync`, `sync` L=0 and `lwsync` L=1 validate their reserved fields and execute a sequentially consistent host fence. GuestMemory completes each access while holding its shared or exclusive lock and the interpreter executes one instruction at a time per context, so the current implementation does not reorder those synchronous accesses. Instruction fetch reads GuestMemory on every step; there is no instruction cache or translated-code cache to invalidate, and newly written bytes are visible on the next fetch. This does not implement the full PowerPC self-modifying-code cache-maintenance sequence. The fence behavior is deliberately stronger and simpler than Xenon's guest memory model; weakly ordered outcomes, device access ordering, `eieio`, MMIO, or CPU/GPU synchronization are not reproduced. The `isync` encoding and refetch behavior were checked against [IBM's `isync` reference](https://www.ibm.com/docs/ssw_aix_72/assembler/idalangref_isync_ics_instrs.html), while `sync` and its L field were checked against [IBM's `sync` reference](https://www.ibm.com/docs/en/aix/7.3.0?topic=set-sync-synchronize-dcs-data-cache-synchronize-instruction).

The cacheless model accepts `dcbst`, `dcbf` and `icbi` as no-ops: GuestMemory stores are already written to the single backing store, and instruction fetch is uncached. `dcbt` and `dcbtst` accept the documented TH values 0, 1, 3, 8 and 10 as non-binding prefetch hints. `dcbz` clears the 128-byte block containing its effective address through `GuestMemory::fill`, which validates the complete write range and invalidates reservation generations. The 128-byte Xenon L1 data-cache line size is recorded in the public [Free60 Xenon Linux hardware description](https://github.com/Free60Project/linux-kernel-xbox360/blob/master/patch-6.17-xenon0.30.diff); the block-zeroing behavior follows IBM's [`dcbz` reference](https://www.ibm.com/docs/en/aix/7.1.0?topic=is-dcbz-dclz-data-cache-block-set-zero-instruction). Tests verify the aligned range, adjacent bytes, out-of-range failure without partial writes, and reservation invalidation. This models guest-visible memory contents, not physical cache state: actual cache levels, privilege behavior, GPU visibility and prefetch performance remain unmodeled. The other opcode assignments and operation descriptions were checked against IBM's [`dcbf`](https://www.ibm.com/docs/no/aix/7.1.0?topic=set-dcbf-data-cache-block-flush-instruction), [`dcbst`](https://www.ibm.com/docs/en/aix/7.1.0?topic=set-dcbst-data-cache-block-store-instruction), [`icbi`](https://www.ibm.com/docs/en/aix/7.2.0?topic=set-icbi-instruction-cache-block-invalidate-instruction) and [`dcbtst`](https://www.ibm.com/docs/en/aix/7.2.0?topic=set-dcbtst-data-cache-block-touch-store-instruction) references.

## XEX2 metadata parser

`loader::parse_xex2` validates the fixed XEX2 header, optional-header directory, security-info bounds, page-descriptor count, file-format information, page descriptors, and the Import Libraries optional header. It extracts Execution Info fields for media/title IDs, title/base versions, platform, executable type, disc number/count and savegame ID, plus TLS template metadata whose allocation sizes and initialized-template range are validated at load time (not initialized for guest threads) and bounded library names, import-record addresses, and type-1 basic-compression descriptors. During load, the record words in PE headers/sections are decoded and checked for a valid image address, matching library index, and supported type. `parse_xex2_file` reads only the declared bounded header, while `load_xex2_file` applies a 512 MiB file-size cap. The loader supports encryption type 0 and compression types 0 and 1. Basic-compressed blocks are reconstructed as stored bytes followed by zero-filled regions, bounded by the XEX image size before allocation; PE import RVAs and section data are read from the reconstructed memory image. Encrypted images and other compression formats are rejected. When page descriptors are present, their 4 KiB or 64 KiB page ranges must cover the PE image; code, data and read-only descriptor permissions are intersected with PE section permissions, and the entry-point page must remain executable. It validates the Xbox PowerPC big-endian PE32 machine/subsystem, image bounds, section ranges, header overlap and section overlap, then transactionally maps pages and copies PE headers/sections into guest memory with read/write/execute permissions. `kernel::GuestExecutor` indexes decoded function-thunk addresses and intercepts calls at their guest PCs; the dispatcher currently supports twenty `xboxkrnl.exe` exports, including ordinal 104 (`KeGetCurrentThread`) and ordinals 267 (`RtlCharToInteger`), 268 (`RtlCompareMemory`), 269 (`RtlCompareMemoryUlong`), 270 (`RtlCompareString`), 284 (`RtlFillMemory`), 285 (`RtlFillMemoryUlong`), 289 (`RtlInitAnsiString`), 290 (`RtlInitUnicodeString`), 293 (`RtlIntegerToUnicodeString`), 298 (`RtlMoveMemory`), 301 (`RtlNtStatusToDosError`), 307 (`RtlUlongByteSwap`), 309 (`RtlUnicodeStringToInteger`), 318 (`RtlUshortByteSwap`), 320 (`RtlZeroMemory`), 338 (`KeTlsAlloc`), 339 (`KeTlsFree`), 340 (`KeTlsGetValue`) and 341 (`KeTlsSetValue`). These TLS services use the current main-thread slot array, bounded to the XEX TLS slot count and the documented 2,048-slot maximum. Allocation and free zero the selected big-endian guest word; inaccessible storage is reported as a guest-memory fault. This is single-thread TLS state only; process-wide allocation and scheduler integration remain incomplete. The TLS export ordinals and behavior were cross-checked against the public [Xenia export table](https://github.com/xenia-project/xenia/blob/master/src/xenia/kernel/xboxkrnl/xboxkrnl_table.inc), [TLS handlers](https://github.com/xenia-project/xenia/blob/master/src/xenia/kernel/xboxkrnl/xboxkrnl_threading.cc) and [kernel TLS slot limit](https://github.com/xenia-project/xenia/blob/master/src/xenia/kernel/kernel_state.cc); no Xenia implementation code is copied. `RtlCompareString` compares counted ANSI bytes and returns a signed ordering result in GPR3, with ASCII-only case folding and explicit rejection of non-ASCII fold requests. Both memory-compare shims return matched byte counts in GPR3; the string initializers read NUL-terminated source strings, enforce counted-string size limits and write 8-byte big-endian descriptors with transactional guest byte stores. `RtlCharToInteger` parses NUL-terminated ASCII with base and prefix handling and stops with an explicit argument error after a defensive 65,536-byte scan cap; `RtlUnicodeStringToInteger` parses a counted UTF-16 buffer. `RtlIntegerToUnicodeString` formats an unsigned ULONG to uppercase digits in the caller's buffer, includes a UTF-16 NUL terminator, updates `Length`, and reports `STATUS_BUFFER_OVERFLOW` with the required length when the capacity is too small. Both conversion helpers report invalid arguments or guest memory faults explicitly. `RtlNtStatusToDosError` currently handles a test-covered subset of common status codes and returns `ERROR_MR_MID_NOT_FOUND` for other values. Unicode string lengths are measured in bytes and remain even. The byte-swap shims reverse 32-bit and 16-bit values and return them zero-extended in GPR3. Fill and move services modify validated guest ranges and return through LR. A synthetic XEX caller exercises thirteen shims, including both UTF-16 integer conversions, the RtlCompareString thunk in both ASCII case modes, and return through LR; ASCII integer parsing and status translation currently have direct unit tests only. Data-import resolution, general thunk rewriting, relocation and most kernel services remain unsupported. This is not yet commercial game startup. XEX import ordinals are cross-checked against the public [XboxDev xboxkrnl.h export list](https://github.com/XboxDev/xbedump/blob/master/xboxkrnl.h) and [RXDK-Libs](https://github.com/Team-Resurgent/RXDK-Libs/blob/main/libs/libkernel/xboxkrnl.def). The counted-string ABI and comparison result contract are cross-checked against [Microsoft's RtlCompareString](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntddk/nf-ntddk-rtlcomparestring) and [STRING](https://learn.microsoft.com/en-us/windows/win32/api/ntdef/ns-ntdef-string). ## Program exceptions and fault reporting

`StepResult` attaches an `ExecutionFault` to interpreter faults. The record classifies illegal and privileged instructions, integer traps, instruction alignment/access faults, data alignment/access faults, unsupported instructions, and internal consistency errors; it includes the faulting PC, fetched word when available, and effective address when applicable. Illegal and privileged instructions enter the PowerPC program exception vector at `0x700`, save SRR0/SRR1, and report a `GuestException`. Matched `tw`, `twi`, `td`, and `tdi` conditions enter the same vector with SRR1's trap syndrome bit set; the word forms compare low 32-bit values and doubleword forms compare all 64 bits. `sc 0` saves CIA+4 to SRR0, saves the architecturally selected MSR bits in SRR1, and enters vector `0xC00`; `rfid` can return to the next guest instruction. Reserved SC fields are rejected, and `sc` LEV=1 returns an unsupported-instruction diagnostic without changing guest state. The current implementation handles illegal/privileged/trap program syndromes, and `rfid` restores a subset of MSR state. SRR0/SRR1 `mfspr`/`mtspr` transfers are restricted when modeled MSR.PR is set.

This is a narrow PowerPC exception subset, not the Xenon exception system: data/instruction access and alignment faults remain host diagnostics, and other exception classes, full MSR behavior, hypervisor/LPES configuration and interrupt delivery are not implemented. System-call encoding and CIA+4/SRR/vector behavior follow the public [PowerPC User ISA, Book I v2.02](https://powerpc.dev/general/PPC_Vers202_Book1_public.pdf) and [Operating Environment Architecture, Book III v2.02](https://powerpc.dev/general/PPC_Vers202_Book3_public.pdf), including the program-interrupt trap syndrome; integer trap fields and conditions are cross-checked against IBM's [twi](https://www.ibm.com/docs/en/aix/7.1.0?topic=set-twi-ti-trap-word-immediate-instruction), [tw](https://www.ibm.com/docs/en/aix/7.2.0?topic=set-tw-t-trap-word-instruction), [td](https://www.ibm.com/docs/en/aix/7.1.0?topic=set-td-trap-double-word-instruction), and [tdi](https://www.ibm.com/docs/en/aix/7.1.0?topic=set-tdi-trap-double-word-immediate-instruction) references. `rfid` encoding and behavior are cross-checked against IBM's [instruction reference](https://www.ibm.com/docs/en/aix/7.3.0?topic=set-rfid-return-from-interrupt-double-word-instruction).

## Integer compare and branch references

The `cmp`/`cmpl` and `cmpi`/`cmpli` implementations follow the architecture's signed/unsigned comparison, L-width, selected-CR-field, and XER summary-overflow behavior. `addc`/`adde` and `addic` forms update XER.CA; `addme` and `addze` add XER.CA as the carry-in, with `addme` also including minus one. `subfc`/`subfe`/`subfic` set CA to the subtraction carry-out (1 means no borrow), while ordinary `subf` leaves CA unchanged. `subfze` adds the one's complement of RA and the carry bit; `subfme` adds the one's complement of RA, the carry bit and all ones. Both extended subtraction forms update CA on every form. OE forms update XER.OV and sticky XER.SO. Immediate `b`/`bc` instructions support relative and absolute targets; `bclr`/`bcctr` apply the decoded BO condition and use aligned LR/CTR targets. Unsupported BO/BH encodings and invalid `bcctr` counter-decrement forms fault explicitly.

The register logical operations use full 64-bit GPR values and update CR0 only in record forms. `slw`/`srw` operate on the low word and zero-extend their result; `sraw` sign-extends the low-word result and updates XER.CA when a negative value loses one bits. `rlwinm` rotates the low word, uses PowerPC's MSB-numbered inclusive mask endpoints and zero-extends the masked word.

`srawi` uses the instruction's five-bit immediate shift count, sign-extends the shifted low word to the 64-bit GPR, and sets XER.CA when a negative source shifts out any one bits. Rc updates CR0, and a zero shift clears CA.

The PPC64 `sld`/`srd` operations use RB's low seven bits as the shift count and return zero for counts 64–127. `srad` uses arithmetic sign fill; XER.CA is set for negative sources when any one bits are shifted out, and for counts 64–127 it follows the sign bit. Immediate `sradi` reconstructs SH from its split encoding, arithmetic-shifts by 0–63, sets XER.CA only when a negative source loses one bits, and clears CA for a zero shift. Rc updates CR0. Unsupported shift instructions remain explicit decode faults.

`cntlzw` counts leading zero bits in the source register's low word, while `cntlzd` counts across the full doubleword. Both return 32 or 64 respectively for a zero source, may update CR0 when Rc is set, and leave XER unchanged. Their reserved RB field is checked by the decoder.

The immediate logical forms use unsigned 16-bit constants: `ori`/`xori`/`andi.` use the low half, while their shifted forms place the immediate in bits 16–31. `andi.` and `andis.` always update CR0 and leave XER unchanged; `ori`, `oris`, `xori`, and `xoris` leave condition and exception state unchanged. The initial multiply subset implements PPC64 `mulli` low-doubleword multiplication, `mullw` low-word multiplication, and signed `mulld` low-doubleword multiplication. `mullw` defines only its low 32-bit result in 64-bit mode, so this interpreter deterministically clears the undefined upper 32 bits. Its OE overflow check uses signed 32-bit representability and Rc compares the signed low-word result. `mulld` supports Rc and OE; overflow updates OV and sticky SO, and Rc records the result in CR0. The `neg` instruction computes the two's-complement negation over the full GPR width; `nego` sets or clears XER.OV when OE is enabled, preserves sticky SO and CA, and detects the signed minimum input without host signed overflow. Rc records the result in CR0.

The integer divide subset implements signed and unsigned word and doubleword forms (`divw`, `divwu`, `divd`, `divdu`), with OE/Rc behavior, sticky XER.SO, OV updates only when OE is set, and CR0 recording. Word division reads the low 32-bit operands and defines only the low 32 bits of the quotient; this implementation clears the ISA-undefined upper destination bits for deterministic tests. The ISA also leaves the result undefined for divide-by-zero and signed-minimum divided by -1. The interpreter chooses zero for such a result, and sets OV when OE is set; this is a documented deterministic policy for undefined outcomes, not a claim that hardware returns zero. Signed C++ division is guarded against those cases to avoid host-language undefined behavior.

The word multiply-high instructions `mulhw` and `mulhwu` compute the high 32 bits of the signed or unsigned 32-bit product. The doubleword forms `mulhd` and `mulhdu` compute the high 64 bits of the signed or unsigned 64-bit product. Their Rc forms compare the result as signed and copy XER.SO to CR0; these instructions do not modify XER. As with other word-result operations, the upper destination half for the word forms is architecturally undefined in PPC64 and is cleared deterministically here. The 64-bit high products are assembled from 32-bit limbs so the implementation remains portable C++20 and does not depend on compiler-specific 128-bit integers.

The initial Xenos frontend component parses the big-endian PM4 packet envelope. It exposes sequential or repeated type-0 register writes, both type-1 register indexes, type-2 no-ops, and type-3 opcode, predicate and payload bounds. A separate application routine applies type-0/type-1 writes plus the type-3 `SET_CONSTANT`, `SET_CONSTANT2` and `SET_SHADER_CONSTANTS` upload formats to a caller-sized register span; it validates packet metadata, complete stream coverage, every payload and the full write set before changing state. PM4 NOP is accepted. `WAIT_FOR_IDLE` accepts one unpredicated dword and completes synchronously because no asynchronous GPU queue exists yet. Unimplemented type-3 opcodes and predicated uploads fail explicitly; predicate execution needs bin-selection state, which is not modeled. `SET_CONSTANT` maps ALU, fetch, boolean, loop and direct-register spaces into the current flat register span; those areas remain provisional until checked against an authoritative Xenos register reference. A separate named register subset currently covers `VGT_MAX_VTX_INDX` (0x2100), `VGT_MIN_VTX_INDX` (0x2101), `VGT_INDX_OFFSET` (0x2102), `VGT_MULTI_PRIM_IB_RESET_INDX` (0x2103), `VGT_DMA_BASE` (0x21FA), `VGT_DMA_SIZE` (0x21FB), and `VGT_DRAW_INITIATOR` (0x21FC). PM4 writes mask reserved bits for this subset; unknown registers retain their raw values. Index transform state reads the low 24 bits of the Xenos offset/min/max registers. This is a narrow draw-state map, not a complete register implementation. A separate decoder extracts `DRAW_INDX` and `DRAW_INDX_2` metadata and validates packet shape. Its state operation transactionally updates the documented `VGT_DRAW_INITIATOR`, `VGT_DMA_BASE` and `VGT_DMA_SIZE` fields. DMA index fetch reads raw physical backing bytes, applies 32-bit swap modes and the supported 16-bit modes, and generates sequential indexes for auto-index draws. The CPU-side `prepare_draw_geometry` operation connects physical DMA/auto-index fetch, topology assembly and the mapped vertex-index transform. Assembly handles point, line, strip, triangle, fan, loop and quad-list topology; it converts fans, loops and quads to indexed ranges and splits modeled line-strip, triangle-strip, fan and line-loop draws at the configured restart value (low 24 bits for 32-bit indices, full value for 16-bit indices). Vertex-index offset/wrap/clamp is applied after restart splitting, before returning CPU-side index ranges; the operation does not submit graphics work. The vertex-fetch subset decodes the two-word buffer descriptor (physical base, dword capacity and endian mode), reads caller-selected physical dword ranges within that capacity, and applies all four Xenos dword endian transformations. The VFETCH index helper selects the encoded source-register lane and converts finite nonnegative indexes by floor or floor(x + 0.5). A separate vertex-shader-index transform models offset addition, 24-bit wrapping and subsequent unsigned min/max clamping; neither helper rewrites the assembled index buffer or is wired into shader execution. A three-dword `VFETCH` decoder extracts the fetch slot, dword stride, signed dword offset, format and control flags. The CPU reader computes indexed dword addresses, distinguishes logical component counts from storage dword counts, reads packed 8/10/11-bit and 16-bit integer/normalized elements, converts IEEE binary16 and the existing 32-bit integer/float formats, and remains bounded by the physical fetch descriptor. Numeric decoding returns source components only and rejects nonzero exponent adjustment. The combined `execute_vertex_fetch_attribute` path selects and rounds the source index, reads and converts the bounded attribute, fills absent lanes from explicit caller-supplied values, and applies X/Y/Z/W, constant 0/1 and destination-preserve swizzles; reserved selector 6 fails. A batch operation maps prepared draw indices through one fetch and stages outputs atomically, rejecting indices outside the exact 24-bit conversion range without exposing partial results. An ordered single-vertex runner executes full VFETCH instructions against a 64-entry temporary-register bank, resolving absolute source/destination registers and fetch-constant slots; relative addressing and missing descriptors fail transactionally. The values for absent lanes remain caller policy until hardware behavior is established, and guest register writes are not yet connected. The alternate signed repeating-fraction mapping fails explicitly. Mini-fetch and predicated instructions fail at decode because inherited state and predicate behavior are not implemented. Tessellation, shader execution and rendering remain unimplemented. Immediate-index and predicated draw packets remain unsupported, and 32-bit swap modes on 16-bit indexes are rejected as ambiguous. Vulkan rendering is not implemented.

The XEX launch scaffold allocates one guest thread's static/dynamic TLS, PCR, a 0xAB0-byte partial KTHREAD block and stack in otherwise unused mapped memory, leaves one guest guard page unmapped, copies the declared TLS template, and initializes `r1`, `r13` and the image entry PC. It fills the documented current-thread PCR pointer and known KTHREAD fields for type, internal list links, stack, TLS, synthetic thread ID 1, and entry point; other KTHREAD fields remain zero. The PCR layout follows the public Xenia `X_KPCR` structure, and its register-13 convention follows Xenia's CPU `ThreadState` initialization ([PCR fields](https://github.com/xenia-project/xenia/blob/master/src/xenia/kernel/xthread.h), [thread register initialization](https://github.com/xenia-project/xenia/blob/master/src/xenia/cpu/thread_state.cc)). The `KeGetCurrentThread` ordinal is cross-checked against the public [XboxDev export list](https://github.com/XboxDev/xbedump/blob/master/xboxkrnl.h). The known offsets and initialization values are cross-checked against the public [Xenia KTHREAD layout](https://github.com/xenia-project/xenia/blob/master/src/xenia/kernel/xthread.h) and [thread initialization routine](https://github.com/xenia-project/xenia/blob/master/src/xenia/kernel/xthread.cc); Project360 does not copy Xenia code. The block is only a data structure: handles, thread startup routines, scheduler, lifecycle, and other KTHREAD fields are not implemented, so this is not complete Xbox process startup.

Packet header, draw-field, register-index, upload-format, vertex-fetch descriptor, endian, VFETCH instruction and vertex-index-remap references were cross-checked against public Xenia format, register, command-processor, primitive-processor, draw-utility, microcode and shader-translator sources; this implementation contains no copied Xenia code: [Xenos packet opcode and vertex-fetch descriptor definitions](https://github.com/xenia-project/xenia/blob/master/src/xenia/gpu/xenos.h), [Xenos draw register fields](https://github.com/xenia-project/xenia/blob/master/src/xenia/gpu/registers.h), [Xenos register indexes](https://github.com/xenia-project/xenia/blob/master/src/xenia/gpu/register_table.inc), [Xenia command processor](https://github.com/xenia-project/xenia/blob/master/src/xenia/gpu/command_processor.cc), [Xenia primitive processing and index endian handling](https://github.com/xenia-project/xenia/blob/master/src/xenia/gpu/primitive_processor.cc), [Xenia vertex-buffer physical addressing](https://github.com/xenia-project/xenia/blob/master/src/xenia/gpu/draw_util.cc), [Xenia VFETCH instruction layout](https://github.com/xenia-project/xenia/blob/master/src/xenia/gpu/ucode.h), [Xenia vertex-shader index remapping](https://github.com/xenia-project/xenia/blob/master/src/xenia/gpu/dxbc_shader_translator.cc), and [Xenia fetch destination-swizzle handling](https://github.com/xenia-project/xenia/blob/master/src/xenia/gpu/shader_translator.cc).

The data subset includes D-form accesses plus indexed `lbzx`, `lhzx`, `lhax`, `lwzx`, `ldx`, `stbx`, `sthx`, `stwx`, and `stdx`; indexed update forms `lbzux`, `lhzux`, `lhaux`, `lwzux`, `ldux`, `stbux`, `sthux`, `stwux`, and `stdux`; byte-reversed `lhbrx`, `lwbrx`, `sthbrx`, and `stwbrx`; D-form `lmw`/`stmw`; and DS-form `ld`/`ldu`/`std`/`stdu`. DS displacement is a signed 14-bit quantity scaled by four; the unsupported `lwa` DS form is diagnosed. Indexed effective addresses add GPR RA and RB, treating RA=0 as a zero base for non-update forms. Update forms reject RA=0; update loads also reject RT=RA. `lmw`/`stmw` transfer GPR RT through GPR 31 as aligned, big-endian words. `lmw` rejects base/destination overlap forms whose result is architecturally undefined. `GuestMemory::read_bytes` validates a complete guest read under one shared lock, supports virtual pages with non-contiguous physical backing, and reports the first invalid guest address without changing the output on failure. `lmw` uses this operation and stages all loaded values before changing registers. `stmw` stages the low words and submits one full-range `GuestMemory::write_bytes` operation, so a mapping or permission failure cannot leave a partial store. Byte accesses may use any address; wider accesses require natural alignment in this prototype. Byte-reversed forms reverse bytes within a naturally aligned halfword or word. Loads zero-extend except for `lha`/`lhau`/`lhax`/`lhaux`, which sign-extend to the 64-bit GPR. D-form and indexed update loads/stores change RA only after successful access. Guest address mapping, permissions, MMIO and the Xbox 360 memory model remain outside this flat buffer.
