# Testing

The dependency-free CTest suite contains `project360_tests` and `project360_library_tests`. When Qt 6 is available, CMake also adds `project360_qt_model_tests`. The CPU test checks small guest programs in memory, including immediate/register arithmetic and multiply (including signed boundaries, low-word/full-product behavior and overflow), byte/halfword/word sign extension, `cntlzw`/`cntlzd` zero and leading-bit cases, immediate/register logical operations, `slw`/`srw`/`sraw`/`srawi`/`sld`/`srd`/`srad` (including immediate and register counts, XER.CA and Rc), `rlwinm`/`rlwimi`/`rlwnm` including wrapping masks, register-controlled rotation and masked insertion, `rldicl`/`rldicr`/`rldic`/`rldimi` including six-bit shifts, six-bit masks, wrapping, insertion, and Rc, `rldcl`/`rldcr` including low-six-bit register shifts, left/right masks and Rc, `mfcr`/`mtcrf` full CR reads and selected-field writes with preservation and reserved-encoding checks, `mcrf` selected CR-field copies with self-copy and preservation checks, all eight CR bitwise operations with complete two-input truth tables, destination/source aliasing, preservation and reserved-Rc checks, `mfspr`/`mtspr` transfers for XER, LR and CTR including XER-width truncation and unsupported-SPR diagnostics, `mcrxr` transfers of the complete XER top nibble into a selected CR field, clearing of those XER bits and preservation of the remainder, signed and unsigned register/immediate compares at 32 and 64 bits, OE/Rc effects, `addze` carry-in, carry-out and OE/Rc behavior, XER carry/overflow behavior, byte/halfword/word/doubleword D-form and indexed loads/stores including update, signed DS displacement, RA=0 D-form addressing, byte-reversed and multiple-word forms, RA=0 indexed addressing, base-register commit on success only, sign extension, invalid update operands, unsupported `lwa` and reserved encodings, alignment and bounds faults, all-or-nothing register results for failed `lmw`, prevalidated stores for failed `stmw`, relative/absolute `b` and `bc`, `bclr`, `bcctr`, CR field preservation, big-endian data and unsupported/reserved instruction faults.

The library-store test covers missing-library startup, adding and reloading absolute UTF-8 paths, duplicate rejection, extension and missing-file validation, removal persistence, and truncated-file rejection without exposing partial entries. The conditional Qt model test covers case-insensitive search, ascending/descending title order, duplicate rejection, model removal, persistence after removal, keeping the original XEX file intact, and deferred file-existence checks for restored library paths. A conditional offscreen Qt window smoke test checks that the library controls exist, unavailable actions start disabled, and the window produces a frame.

From a Windows Developer PowerShell with CMake 3.24+ and Visual Studio 2026 C++ tools installed:

```powershell
cmake --preset windows-debug
cmake --build --preset debug
ctest --preset debug --output-on-failure
cmake --build --preset release
ctest --test-dir out/build/windows-debug -C Release --output-on-failure
```

Latest local validation on Windows/MSVC: Debug and Release builds succeeded, both locally available CTest cases passed in each configuration, and the Debug smoke executable printed `r3=7 r4=12 r5=19`. The optional Qt GUI and conditional Qt tests are not part of these local passes because Qt 6 is not installed on this PC. The `Windows Qt build` workflow passed remotely on Qt 6.10.3/MSVC 2022: Debug and Release builds succeeded, and model plus offscreen window smoke tests passed in both configurations ([run 42451851613](https://github.com/matheusmoreira88/Project360/actions/runs/42451851613)). This verifies compilation, model behavior, window construction, and offscreen frame rendering; it is not a manual visual review.

These tests are not evidence for instructions outside the listed subset, timing behavior, multi-threaded execution, or Xbox 360 game compatibility. Add one test per implemented instruction and targeted boundary tests as semantics expand.
