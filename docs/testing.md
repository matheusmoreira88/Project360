# Testing

The dependency-free CTest suite contains `project360_tests`, `project360_gpu_tests`, `project360_memory_tests`, `project360_kernel_tests`, `project360_loader_tests` and `project360_library_tests`. When Qt 6 is available, CMake also adds `project360_qt_model_tests`. The CPU test checks small guest programs in memory, including immediate/register arithmetic and multiply (signed boundaries, low-word results, high-word and doubleword high products, doubleword wrap and overflow), `neg`/`nego` ordinary and signed-minimum behavior, register aliasing, OE/Rc, CR0 and XER preservation, signed and unsigned word/doubleword division (truncation, zero extension, register aliasing, CR0, XER.OV/SO/CA and architecturally undefined cases), byte/halfword/word sign extension, `cntlzw`/`cntlzd` zero and leading-bit cases, immediate/register logical operations, `slw`/`srw`/`sraw`/`srawi`/`sld`/`srd`/`srad`/`sradi` (including split six-bit immediate, zero/max counts, XER.CA and Rc), `rlwinm`/`rlwimi`/`rlwnm` including wrapping masks, register-controlled rotation and masked insertion, `rldicl`/`rldicr`/`rldic`/`rldimi` including six-bit shifts, six-bit masks, wrapping, insertion, and Rc, `rldcl`/`rldcr` including low-six-bit register shifts, left/right masks and Rc, `mfcr`/`mtcrf` full CR reads and selected-field writes with preservation and reserved-encoding checks, `mcrf` selected CR-field copies with self-copy and preservation checks, all eight CR bitwise operations with complete two-input truth tables, destination/source aliasing, preservation and reserved-Rc checks, `mfspr`/`mtspr` transfers for XER, LR and CTR including XER-width truncation and unsupported-SPR diagnostics, `mcrxr` transfers of the complete XER top nibble into a selected CR field, clearing of those XER bits and preservation of the remainder, signed and unsigned register/immediate compares at 32 and 64 bits, OE/Rc effects, `addze` carry-in, carry-out and OE/Rc behavior, XER carry/overflow behavior, byte/halfword/word/doubleword D-form and indexed loads/stores including update, scalar FPR `lfs`/`lfd`/`stfs`/`stfd` transfers in D and indexed forms, binary32 widening/binary64 preservation, update rules and alignment faults, bit-exact `fmr`/`fneg`/`fabs`/`fnabs` operations including NaN payload preservation and Rc-to-CR1 behavior, signed DS displacement, RA=0 D-form addressing, byte-reversed and multiple-word forms, RA=0 indexed addressing, base-register commit on success only, sign extension, invalid update operands, unsupported `lwa` and reserved encodings, alignment and bounds faults, all-or-nothing register results for failed `lmw`, prevalidated stores for failed `stmw`, relative/absolute `b` and `bc`, `bclr`, `bcctr`, CR field preservation, big-endian data, unsupported/reserved instruction faults, and structured instruction-fetch, illegal-instruction, data-alignment and data-access fault metadata. Floating-point arithmetic and general FPSCR control are not covered because they are not implemented.

The GPU test decodes a mixed big-endian PM4 stream and checks type-0 sequential register packets, type-1 two-register packets, type-2 no-ops, type-3 opcode/predicate/payload metadata, the empty zero header, incomplete payloads and partial dwords. It applies type-0 sequential and repeated writes, type-1 indexed writes, and the type-3 `SET_CONSTANT` banks plus `SET_CONSTANT2`/`SET_SHADER_CONSTANTS` direct offsets to a caller-sized register array. It verifies that unsupported constant banks, stale metadata, incomplete packet lists, out-of-range writes, unimplemented draw opcodes and predicated uploads fail without changing prior register values. It validates packet framing and these upload formats only, not general Xenos register semantics or graphics output.

The CPU exception scenario runs an illegal instruction, verifies SRR0/SRR1 and vector `0x700`, executes a small handler, restores SRR state through `rfid`, and resumes the guest program. It also verifies the privileged-instruction program exception for `rfid` and problem-state SRR0 access. A separate `sc 0` program verifies the next-instruction SRR0, saved MSR bits, system-call vector `0xC00`, handler execution, `rfid` return and resumption after the call; `sc` LEV=1 is reported unsupported. These checks cover only the implemented PowerPC exception subset; memory access/alignment faults remain host-side diagnostics and syscall dispatch is not yet connected to the kernel import dispatcher.

The memory tests cover aligned/valid page mapping, virtual aliases, big-endian data visibility, unmapped-page rejection, permission changes, execute-only fetches, translation access checks, all-or-none multi-page mapping batches, and transactional byte/pattern fills and byte stores spanning non-contiguous backing pages. Word-pattern checks verify guest big-endian byte order, alignment/length constraints and failure atomicity across a protected page. Guest moves cover overlap in both directions, bounded scratch storage behavior, non-contiguous cross-page mappings and no partial destination writes when a later page is protected. A CPU integration test executes `addi` from a mapped virtual page and confirms that removing execute permission prevents fetch. The page model remains a generic prototype and does not claim Xenon MMU behavior.

The kernel unit test invokes `xboxkrnl.exe` ordinals 268, 269, 284, 285, 289, 290, 298, 307, 318 and 320 directly with Xenon argument registers. It verifies `RtlCompareMemory` for equal and differing blocks, matching-prefix count, invalid ranges and inaccessible memory; `RtlCompareMemoryUlong` for repeated word matches, first mismatch and its documented zero result on unaligned sources or lengths not divisible by four; `RtlFillMemory` including its low-byte fill value; `RtlFillMemoryUlong` alignment, repeated pattern and guest big-endian order; both counted-string initializers for null and ordinary strings, correct byte lengths, oversized-source capping, memory faults and unchanged output on a failed scan; both byte-swap helpers for value widths, zero extension and LR return; `RtlMoveMemory` copying and LR return; `RtlZeroMemory`; unsupported imports; 32-bit pointer validation; and no partial writes on protected cross-page destinations. The loader integration fixture contains ten XEX import records and a tiny PPC caller. The guest executor calls each imported shim, checks byte fill, word pattern, comparison results, copied bytes, both string descriptors and byte-swap results, then resumes at the caller's LR. This verifies only a synthetic unencrypted XEX and these ten implemented exports.

The XEX loader tests build in-memory XEX2 and Xbox PE32 fixtures and check metadata extraction plus truncated input, unknown/unsupported signatures, excessive sizes/counts, malformed security blocks, malformed import-library tables and names, descriptor overflow, duplicate execution metadata, invalid PE machine types, entry points, out-of-range sections, section data overlapping headers, and overlapping virtual sections. Import checks cover library names, versions, record addresses, type, index, ordinal, invalid record types and addresses. Tests load a synthetic unencrypted/uncompressed XEX image from memory and from a temporary file, verify page permissions and bytes, and execute a PPC caller through imported `RtlCompareMemory`, `RtlCompareMemoryUlong`, `RtlFillMemory`, `RtlFillMemoryUlong`, `RtlInitAnsiString`, `RtlInitUnicodeString`, `RtlMoveMemory`, `RtlUlongByteSwap`, `RtlUshortByteSwap` and `RtlZeroMemory` thunks. The integration case also uses `GuestExecutor::run` to execute the complete synthetic program, verify all ten calls, and stop at exact instruction budgets. Encrypted input is rejected before the memory map changes. `--inspect-xex` performs metadata inspection; `--run-xex` uses the file loader and a one-million-instruction budget. No commercial image or protected content is included.

The library-store test covers missing-library startup, adding and reloading absolute UTF-8 paths, duplicate rejection, extension and missing-file validation, removal persistence, and truncated-file rejection without exposing partial entries. The conditional Qt model test covers case-insensitive search, ascending/descending title order, duplicate rejection, model removal, persistence after removal, keeping the original XEX file intact, and deferred file-existence checks for restored library paths. A conditional offscreen Qt window smoke test checks that the library controls exist, unavailable actions start disabled, and the window produces a frame.

From a Windows Developer PowerShell with CMake 3.24+ and Visual Studio 2026 C++ tools installed:

```powershell
cmake --preset windows-debug
cmake --build --preset debug
ctest --preset debug --output-on-failure
cmake --build --preset release
ctest --test-dir out/build/windows-debug -C Release --output-on-failure
```

Latest local validation on Windows/MSVC: Debug and Release builds succeeded, all five locally configured CTest targets passed in both configurations, and the Debug smoke executable printed `r3=7 r4=12 r5=19`. The optional Qt GUI and conditional Qt tests are not part of these local passes because Qt 6 is not installed on this PC. The `Windows Qt build` workflow passed remotely on Qt 6.10.3/MSVC 2022: Debug and Release builds succeeded, and model plus offscreen window smoke tests passed in both configurations ([run 42451851613](https://github.com/matheusmoreira88/Project360/actions/runs/42451851613)). This verifies compilation, model behavior, window construction, and offscreen frame rendering; it is not a manual visual review.

These tests are not evidence for instructions outside the listed subset, timing behavior, multi-threaded execution, or Xbox 360 game compatibility. Add one test per implemented instruction and targeted boundary tests as semantics expand.
