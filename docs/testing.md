# Testing

The dependency-free CTest suite contains `project360_tests`, `project360_gpu_tests`, `project360_memory_tests`, `project360_kernel_tests`, `project360_loader_tests` and `project360_library_tests`. When Qt 6 is available, CMake also adds `project360_qt_model_tests`. The CPU test checks small guest programs in memory, including immediate/register arithmetic and multiply (signed boundaries, low-word results, high-word and doubleword high products, doubleword wrap and overflow), `neg`/`nego` ordinary and signed-minimum behavior, register aliasing, OE/Rc, CR0 and XER preservation, signed and unsigned word/doubleword division (truncation, zero extension, register aliasing, CR0, XER.OV/SO/CA and architecturally undefined cases), byte/halfword/word sign extension, `cntlzw`/`cntlzd` zero and leading-bit cases, immediate/register logical operations, `slw`/`srw`/`sraw`/`srawi`/`sld`/`srd`/`srad`/`sradi` (including split six-bit immediate, zero/max counts, XER.CA and Rc), `rlwinm`/`rlwimi`/`rlwnm` including wrapping masks, register-controlled rotation and masked insertion, `rldicl`/`rldicr`/`rldic`/`rldimi` including six-bit shifts, six-bit masks, wrapping, insertion, and Rc, `rldcl`/`rldcr` including low-six-bit register shifts, left/right masks and Rc, `mfcr`/`mtcrf` full CR reads and selected-field writes with preservation and reserved-encoding checks, `mcrf` selected CR-field copies with self-copy and preservation checks, all eight CR bitwise operations with complete two-input truth tables, destination/source aliasing, preservation and reserved-Rc checks, `mfspr`/`mtspr` transfers for XER, LR and CTR including XER-width truncation and unsupported-SPR diagnostics, `mcrxr` transfers of the complete XER top nibble into a selected CR field, clearing of those XER bits and preservation of the remainder, signed and unsigned register/immediate compares at 32 and 64 bits, OE/Rc effects, `addme`/`addze`/`subfme`/`subfze` carry-in, carry-out and OE/Rc behavior, XER carry/overflow behavior, byte/halfword/word/doubleword D-form and indexed loads/stores including update, scalar FPR `lfs`/`lfd`/`stfs`/`stfd` transfers in D and indexed forms, binary32 widening/binary64 preservation, update rules and alignment faults, bit-exact `fmr`/`fneg`/`fabs`/`fnabs` operations including NaN payload preservation and Rc-to-CR1 behavior, signed DS displacement, RA=0 D-form addressing, byte-reversed and multiple-word forms, RA=0 indexed addressing, base-register commit on success only, sign extension, invalid update operands, unsupported `lwa` and reserved encodings, alignment and bounds faults, all-or-nothing register results for failed `lmw`, prevalidated stores for failed `stmw`, and `lmw`/`stmw` transfers across non-contiguous physical backing pages plus unmapped-page fault cases, including atomic byte reads and first-fault reporting, `lswi`/`lswx`/`stswi`/`stswx` byte counts, zero-count/zero-means-32 rules, wraparound, low-word order, partial-word zero fill, invalid load overlaps and all-or-nothing memory faults, relative/absolute `b` and `bc`, `bclr`, `bcctr`, CR field preservation, big-endian data, unsupported/reserved instruction faults, and structured instruction-fetch, illegal-instruction, data-alignment and data-access fault metadata. Floating-point arithmetic and complete FPSCR exception delivery are not implemented; tests cover only the explicitly listed FPSCR transfer and control instructions.

Kernel dispatcher tests cover RtlCompareMemory prefix results across non-contiguous mappings, multiple bounded comparison chunks, and an early mismatch before a later unmapped page.

The synthetic XEX integration test also changes a decoded import record to the data-import type and verifies that attempting to execute it returns an explicit fault while leaving the guest PC unchanged. Data imports are parsed as metadata but are not resolved or executable services.

CPU tests verify `mfmsr` decoding, complete MSR transfer in supervisor state, reserved-field rejection, and privileged exception entry from problem state without modifying its target GPR. `mtmsrd` tests cover the L=1 EE/RI write mask, preservation of other MSR bits, unsupported L=0 behavior, reserved encodings, and privileged exception entry without an MSR write.

The floating-point transfer tests verify optional PowerPC `stfiwx` indexed storage byte-for-byte, including unchanged FPR, CR and FPSCR state, plus reserved-record-bit rejection and misaligned-store fault behavior. FPSCR tests also exercise `mcrfs` field extraction and sticky-flag clearing, `mtfsfi` field writes, `mtfsf` masked FPR-to-FPSCR field copies, `mtfsb0`/`mtfsb1` bit changes, FX preservation, derived FEX/VX summaries, record-form CR1, MSR[FP] gating, reserved encodings, literal opcodes, and explicit unsupported VXSOFT exception cases. These tests do not imply complete floating-point exception handling.

PowerPC reservation tests execute `lwarx`/`stwcx.` and `ldarx`/`stdcx.` success and no-reservation failure, verify CR0.EQ/SO handling, reject mismatched targets, and ensure an intervening write within the selected 4 KiB backing-page reservation granule forces the conditional store to fail. The doubleword tests also check 8-byte alignment and reserved record-bit encodings. Memory tests exercise word reservations through virtual aliases. Concurrent tests run two independent interpreter states that each increment one shared guest word and one shared guest doubleword 1,000 times through retrying conditional-store loops, then verify exact totals of 2,000. This covers GuestMemory's host locking and reservation mechanism, but does not validate Xenon scheduling or weak-memory behavior.

Storage-barrier tests decode `isync`, `sync` L=0 and `lwsync` L=1, reject nonzero reserved fields and Rc, and execute the barriers before a following guest instruction while checking that register state is preserved. A small self-modifying guest sequence writes a new instruction into GuestMemory, executes `isync`, and verifies the next interpreter step fetches the new word. Cache-operation tests cover `dcbst`, `dcbf`, `icbi`, `dcbt` and `dcbtst`, including reserved fields and accepted/rejected TH hints; they verify the current cacheless model leaves guest registers and data unchanged. `dcbz` tests verify the 128-byte aligned block, adjacent-byte preservation, failure on an incomplete backing range without partial writes, and invalidation of a reservation in the cleared block. These tests do not validate actual Xenon cache state, privilege behavior, GPU visibility, weak-memory behavior or MMIO ordering. The three barriers map to a conservative sequentially consistent host fence.

The GPU test decodes a mixed big-endian PM4 stream and checks type-0 sequential register packets, type-1 two-register packets, type-2 no-ops, type-3 opcode/predicate/payload metadata, the empty zero header, incomplete payloads and partial dwords. It applies type-0 sequential and repeated writes, type-1 indexed writes, and the type-3 `SET_CONSTANT` banks plus `SET_CONSTANT2`/`SET_SHADER_CONSTANTS` direct offsets to a caller-sized register array. The draw metadata decoder checks `DRAW_INDX` query-token and DMA base/size fields and `DRAW_INDX_2` auto-index fields; malformed initiators and immediate-index draws fail explicitly. Draw state application updates the modeled initiator and DMA registers transactionally, rejects inconsistent metadata and preserves DMA registers for auto-index draws. Index-fetch tests cover 16-bit no-swap and 8-in-16, all four 32-bit swap modes, direct physical reads despite CPU virtual mapping, auto-index generation, unsupported 16-bit 32-bit-swap modes, declared index-count limits, and out-of-range DMA memory. Packet tests also verify unsupported constant banks, stale metadata, incomplete packet lists, out-of-range writes, unsupported draw application and predicated uploads fail without changing prior register values. `WAIT_FOR_IDLE` is accepted only with one unpredicated payload dword; it completes immediately because the frontend applies work synchronously and has no asynchronous GPU queue. These tests validate selected metadata and index input only, not primitive restart, vertex processing, shaders or graphics output.

The loader integration test initializes a main-thread launch context from a synthetic XEX, checks that known nonzero TLS template bytes are copied and the template tail is zero-filled, reads back PCR TLS/self/current-thread/stack fields and the modeled KTHREAD type, TLS, stack, ID and start address, verifies initial `r1`/`r13`/PC, confirms that the guard page is unmapped, and checks that an allocation failure leaves CPU state unchanged. It validates only the initialized KTHREAD fields; thread creation, handles, scheduler state and compatibility with a commercial title remain untested.

The CPU exception scenario runs an illegal instruction, verifies SRR0/SRR1 and vector `0x700`, executes a small handler, restores SRR state through `rfid`, and resumes the guest program. It also verifies the privileged-instruction program exception for `rfid` and problem-state SRR0 access. A separate `sc 0` program verifies the next-instruction SRR0, saved MSR bits, system-call vector `0xC00`, handler execution, `rfid` return and resumption after the call; `sc` LEV=1 is reported unsupported. These checks cover only the implemented PowerPC exception subset; memory access/alignment faults remain host-side diagnostics and syscall dispatch is not yet connected to the kernel import dispatcher.

The memory tests cover aligned/valid page mapping, virtual aliases, big-endian data visibility, unmapped-page rejection, permission changes, execute-only fetches, translation access checks, all-or-none multi-page mapping batches, and transactional byte/pattern fills and byte stores spanning non-contiguous backing pages. Word-pattern checks verify guest big-endian byte order, alignment/length constraints and failure atomicity across a protected page. Guest moves cover overlap in both directions, bounded scratch storage behavior, non-contiguous cross-page mappings and no partial destination writes when a later page is protected. A CPU integration test executes `addi` from a mapped virtual page and confirms that removing execute permission prevents fetch. The page model remains a generic prototype and does not claim Xenon MMU behavior.

The kernel unit tests cover PowerPC-ABI argument handling, guest-memory faults, LR returns, TLS and clock behavior, and selected `Rtl*` services. Pool (9/10/15), clock (130–132), TLS (338–341) and the selected `Rtl*` ordinals are checked against the pinned Xbox 360 export map in `docs/kernel_exports.md`. The dispatcher rejects unlisted ordinals, including historical aliases that previously pointed at different exports. Synthetic XEX tests validate only their encoded fixture and dispatcher behavior; they are not proof of external homebrew compatibility.

The `RtlCompareString` tests also cover empty strings with null buffers and inaccessible descriptors; guest state remains unchanged whenever descriptor or content reads fail.

The XEX loader tests validate bounded XEX2/PE parsing, metadata, imports, permissions and malformed-input rejection. Synthetic unencrypted XEX images exercise supported imports through decoded thunk addresses, including pool allocation/free and selected clock, TLS and `Rtl*` calls; these tests do not execute a complete external program. `GuestExecutor::run` budget and fault behavior are checked separately. Encrypted input and unsupported compression are rejected before the memory map changes. `--inspect-xex` performs metadata inspection; `--run-xex` uses the file loader and a one-million-instruction budget. No commercial image or protected content is included.

The library-store test covers missing-library startup, adding and reloading absolute UTF-8 paths, duplicate rejection, extension and missing-file validation, removal persistence, and truncated-file rejection without exposing partial entries. The conditional Qt model test covers case-insensitive search, ascending/descending title order, duplicate rejection, model removal, persistence after removal, keeping the original XEX file intact, and deferred file-existence checks for restored library paths. A conditional offscreen Qt window smoke test checks that the library controls exist, unavailable actions start disabled, and the window produces a frame.

From a Windows Developer PowerShell with CMake 3.24+ and Visual Studio 2026 C++ tools installed:

```powershell
cmake --preset windows-debug
cmake --build --preset debug
ctest --preset debug --output-on-failure
cmake --build --preset release
ctest --test-dir out/build/windows-debug -C Release --output-on-failure
```

Latest local validation on Windows/MSVC: Debug and Release builds succeeded, all six locally configured CTest targets passed in both configurations, and the Debug smoke executable printed `r3=7 r4=12 r5=19`. The optional Qt GUI and conditional Qt tests are not part of these local passes because Qt 6 is not installed on this PC. The `Windows Qt build` workflow passed remotely on Qt 6.10.3/MSVC 2022: Debug and Release builds succeeded, and model plus offscreen window smoke tests passed in both configurations ([run 42451851613](https://github.com/matheusmoreira88/Project360/actions/runs/42451851613)). This verifies compilation, model behavior, window construction, and offscreen frame rendering; it is not a manual visual review.

These tests are not evidence for instructions outside the listed subset, timing behavior, multi-threaded execution, or Xbox 360 game compatibility. Add one test per implemented instruction and targeted boundary tests as semantics expand.
The XEX integration test starts a second PPC caller at the fixture's added code section, calls the ordinal-270 import thunk twice, and checks both the case-insensitive equality result and the sign-extended case-sensitive ordering result after returning to guest instructions.

A separate bounded program test executes six PowerPC instructions plus a kernel import: it sets arguments with `addi`/`addis`/`ori`, branches with link to the verified `RtlFillMemoryUlong` thunk, checks the big-endian guest-memory write, and confirms execution resumes at the instruction after the call. This is a synthetic executor test; it does not parse or run an external homebrew XEX.

The dispatcher tests cover clock exports, including monotonic interrupt time, big-endian system time and the 49,875,000-tick frequency, and TLS allocation/free/get/set with reuse, exhaustion, big-endian storage and memory-fault cases. A synthetic XEX initializes the main-thread context and executes all four TLS imports through thunk addresses. These checks validate the single-thread TLS array only; they do not validate system-wide scheduling or external title startup.
